# AWS starter path for TRACE

The current app stores report data in a browser-only demo. Deploy it with sample data only. Private claim answers and shared reports require a backend before public use. A Cognito user directory has been manually created in Asia Pacific (Singapore) for controlled testing. The environment-gated OIDC session now controls Sign In, My Account, and Sign Out and returns users to the requested route. In Cognito mode, old demo sessions are ignored and report/claim/dashboard/admin routes show an unavailable-online notice after sign-in. This does not implement backend authorization.

For local sign-in testing, fill the ignored `.env.local` from `.env.example`, including the managed-login domain. Register `http://localhost:5173/` in the app client's allowed callback URLs and allowed sign-out URLs; restart Vite. Open the homepage, select Sign In, then Continue to Sign In and use an invited test account. Confirm My Account and Sign Out work. Simulated browser tests pass, but the actual AWS login/logout and allowed sign-out configuration still need verification. See [aws-deployment-inventory.md](./aws-deployment-inventory.md).

Current priority is local workflow correctness and the Mandaluyong Community Board demo; AWS comes afterward. The board currently uses separate browser-local storage, with no shared posts, real moderation authority, or government partnership. A future backend must enforce author/admin permissions and confirmed persistence for posts as well as reports/claims. Do not expose the current demo admin shortcut as production authentication.

The local demo supports optional claimant-owned lost-report links, finder reference details, and self-review restrictions. A server-only PostgreSQL repository now uses transactions and unique indexes for local claim/handoff checks; it has no authenticated HTTP API or frontend connection. See [postgres-local.md](./postgres-local.md) for tests and remaining security work.

Start with the [AWS service inventory](./aws-services.md): it explains each service's purpose and which additions can wait. Follow the detailed acceptance criteria in [AGENTS.md](../AGENTS.md).

Keep [aws-deployment-inventory.md](./aws-deployment-inventory.md) current whenever an AWS resource is created, changed, or deleted. It must not contain resource identifiers, credentials, or account details.

1. Define and test backend contracts, public/private responses, permission rules, and consistent claim/handoff operations locally. Keep the demo available through a separate data adapter.
2. In AWS Billing, check your actual Free Tier plan, credits, and expiry. Create an [AWS Budget](https://aws.amazon.com/aws-cost-management/aws-budgets/pricing/) alert before creating resources; alerts do not cap spending.
3. Add reproducible infrastructure for [Cognito](https://aws.amazon.com/cognito/pricing/) sign-in, an [API Gateway HTTP API](https://aws.amazon.com/api-gateway/pricing/) with [Lambda](https://aws.amazon.com/lambda/pricing/) for authorization and claim decisions, [RDS for PostgreSQL](https://aws.amazon.com/rds/postgresql/pricing/) as the candidate for records/audit, and a private [S3](https://aws.amazon.com/s3/pricing/) bucket for photos. Include scoped IAM roles and CloudWatch logging. Evaluate Cognito Lite as the initial plan. Review RDS compute, storage, backup, network, and idle costs before provisioning.
4. Run the existing match ranking in Lambda with bounded candidate queries. Keep ownership approval and handoff recording restricted to admins. Replace production `src/lib/store.tsx` browser persistence with API calls.
5. Commit and push the verified repository to GitHub. Connect that branch to [Amplify Hosting](https://aws.amazon.com/amplify/pricing/). Use `npm ci` and `npm run build`; the output folder is `dist`. Configure SPA rewrites, API origins, and Cognito callbacks. Verify direct item links, real sign-in, private data isolation, photo access, and the complete return workflow.

Use one AWS Region for the backend. Start with the Amplify default domain. Add custom DNS, WAF, application email delivery, and EventBridge only when their features are needed; each can add cost. The expanded alternative is in [architecture.md](./architecture.md).
